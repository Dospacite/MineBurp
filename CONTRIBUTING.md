# Contributing

Keep dependencies pointing inward as described in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Protocol code must not depend on Tauri, project storage, or launcher behavior.

Before submitting a change, run:

```bash
npm run build:agent
npm run prepare:sidecar
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
npm run typecheck
npm run lint
npm run test
npm run build
npm run test:agent
```

On a Linux machine with the Tauri system prerequisites installed, also run `npm run tauri -- build --no-bundle`.

Packet mappings should cite an authoritative artifact in the change description. Add raw fixtures or round-trip tests for framing, encryption, and version-specific layouts. A decoder failure must preserve raw bytes and return a visible error.

Project schema changes require a forward-only migration and tests that open the previous schema. Never rewrite or delete a user's existing `.mineburp` file as part of migration failure handling.

## Development setup

Install Node.js 22, npm, the Rust toolchain in `rust-toolchain.toml`, JDK 21,
Git, and the [Tauri Linux prerequisites](https://v2.tauri.app/start/prerequisites/).
Run `npm ci`, then `npm run tauri dev`. The build prepares the MCP sidecar and
Java agent automatically. The Java agent targets Java 8 despite using JDK 21
to compile. Linux is the supported capture platform.

Install `dumpcap` through your distribution and grant capture permission to your
regular account. Never launch the desktop as root.

- Debian/Ubuntu: install `wireshark-common`, run `sudo dpkg-reconfigure wireshark-common`, allow non-root capture, then `sudo usermod -aG wireshark "$USER"`.
- Arch: install `wireshark-cli` and add your user to the `wireshark` group with `sudo usermod -aG wireshark "$USER"`.
- Fedora: install `wireshark-cli` and run `sudo usermod -aG wireshark "$USER"`.

Log out and back in after group changes. Check `dumpcap -D` as your normal user.
If the distribution does not configure capabilities, an administrator can use
`sudo setcap cap_net_raw,cap_net_admin=eip "$(which dumpcap)"`. Package upgrades
may reset that setting; prefer the distribution's group setup.

## Testing without Minecraft

`cargo test --workspace`, `npm run test`, and `npm run test:agent` need no game
account or running Minecraft instance. Import a pcap/pcapng through the project
menu to exercise reassembly, filtering and export; encrypted captures remain raw.
A MineBurp pcapng export preserves decoded session metadata on re-import.

For live protocol tests, start the desktop, connect an MCP client as described in
[docs/MCP.md](docs/MCP.md), and call `route host="127.0.0.1" port=25565` against
your own offline-mode lab server. Connect a headless protocol client to the
returned listener within 15 seconds. Each route accepts one client. No Java
agent is needed for that offline-mode lab. Optional local fixtures under
`test-projects/` are not a prerequisite or distributed dependency. See the
[active testing tutorial](docs/TUTORIAL.md).

## Adding a Tauri command

Implement the command adapter in `src-tauri/src/`, then keep these four pieces
synchronized:

1. Add its snake_case name to `COMMANDS` in `src-tauri/build.rs`.
2. Grant `allow-command-name` in `src-tauri/capabilities/default.json`.
3. Register the command in `tauri::generate_handler!` in `src-tauri/src/lib.rs`.
4. Build the desktop to regenerate `src-tauri/permissions/autogenerated/`
   permission TOML and references, and include the generated changes.

Do not hand-edit generated permission files. The unit test in `lib.rs` compares
the command, capability and handler lists; run it before submitting.

## Pull requests

Use focused commits with an imperative subject. Explain the triggering behavior,
the resulting change, and the checks you ran. Include screenshots for UI changes
and authoritative protocol sources for mappings. Document unverified checks and
new runtime dependencies. Keep secrets and captured private traffic out of
fixtures, logs, and issue reports. CI builds all fuzz targets on PRs and runs
each for about 60 seconds nightly. Run `cargo deny check` and
`npm audit --omit=dev --audit-level=high` when changing dependencies.

## Releasing

The workspace package version in `Cargo.toml` is authoritative. Tauri 2 reads the
`src-tauri` Cargo package version when its config omits `version`, as documented
in the [Tauri configuration reference](https://v2.tauri.app/reference/config/#version).

1. Run `npm run bump:version -- X.Y.Z`. This updates the workspace version,
   `package.json`, and both root version entries in `package-lock.json`.
2. Run `cargo metadata --format-version 1 > /dev/null` to refresh workspace
   versions in `Cargo.lock`, and commit that lockfile with the version changes.
3. Move the release notes from Unreleased into `## [X.Y.Z] - YYYY-MM-DD` in
   `CHANGELOG.md`. Add its release link and leave a fresh Unreleased section.
4. Run the checks above, including `npm run tauri -- build --no-bundle`, and
   merge the release commit. Tag it with `git tag vX.Y.Z`, then
   `git push origin vX.Y.Z`.
5. Review the draft GitHub release before publishing. The Linux workflow builds
   the agent, MCP sidecar, AppImage and deb, attaches CycloneDX SBOMs and
   SHA256SUMS, and attests the artifacts. Verify checksums and install both
   packages on a clean Linux machine. Debian packages depend on
   `wireshark-common` for dumpcap; AppImage users must install it separately.

The scheduled packet-table job downloads upstream data with offline mode disabled
and opens a review PR. Repository settings must allow Actions to create PRs.
Review generated data and its upstream sources before merging.
